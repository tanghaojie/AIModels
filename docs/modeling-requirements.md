# 建筑建模、材质、定位与拼装动画详细要求

这是 AIModels 后续建筑制作的执行要求。开始新模型或明确委托重制时，先复制[逐建筑任务书](templates/model-brief.md)，填清资料、范围和验收，再制作。本文可独立用于建模，不要求建模者先读另一仓库。既有资产和历史验收记录保留原样，不能仅因增加规范就称已整改。

标准编号 **CS-AM-1**，修订日期 **2026-10-17**。Cyber-Sight 的[制作主规范](https://github.com/tanghaojie/Cyber-Sight/blob/master/docs/platform/design/modules/geo-model-authoring.md)及[分件动画专题](https://github.com/tanghaojie/Cyber-Sight/blob/master/docs/platform/design/modules/geo-model-assembly-authoring.md)维护消费约束；AIModels 保存本执行版和逐建筑任务书。修改双方约定时同步编号、修订日期和能力说明，不能仅修改一侧文档就声称软件已支持。

“必须”是新交付的验收条件；“建议/默认提案”是可按真实建筑、资料、镜头和设备调整的起点，最终值写入任务书。默认新建筑同时交付静态完整模型、爆炸分解和构件飞入拼装；维护者明确只要静态时记录不适用范围及原因。

## 1. 需求来源与效果目标

维护者要求读取[Blender建筑爆炸动画](chatgpt-conversation://6ad2cbc7-5560-83e9-a3c3-6afb06ff711e)并同步到两个项目。2026-10-17 已读取全部两轮用户消息：

> 我想实现建筑爆炸体一点一点搭建出来的过程，使用 blender 动画可以吗
>
> 我想实现建筑从无到有、构件逐步飞入拼装的 Blender 动画，请给我具体实现方案和可运行脚本。

会话助手正文只返回内容引用，没有取得原方案或可运行脚本。本规范的分件方法、命名、帧率、时长和参数是本次细化，不能当作原会话已确认数值。此轮交付要求文档，后续实际模型才交付自己的可运行脚本。

目标是可用于建筑展示、环绕近看、昼夜录屏及逐件拼装的完整资产。先保证建筑身份、比例和轮廓，再补细部、材质与镜头效果。爆炸是有秩序的分解图，不默认碎裂、坍塌、烟火或物理破坏；结构资料不足时明确为展示性构造，不称测绘、BIM 或真实施工模拟。

## 2. 资料、精度与几何

- 保存建筑名称、所在地、建成/设计状态、参考日期、主体高度、宽深、层数、轮廓、北向、入口、裙房、冠部及屋面依据。可靠来源与照片估算分开记录，缺项写未知。
- 参考原图保存到 `references/`，附来源 URL、采集日期、作者/机构、许可、用途、支持的尺寸/造型和估算说明；不能只留下网页链接。不能随 Git 分发的资料列明本地保留原因和可复现获取方式。
- 核对正面、背面、侧面、鸟瞰和地面入口；细节数量不能掩盖楼高、塔楼倾斜、核心洞口、结构、裙房或朝向错误。设计图与建成状态不混用。
- 采用米制，Blender Unit Scale=1、Length=Meters，常规成品 scale=1。局部顶点靠近原点，不把经纬度或 ECEF 大坐标写入顶点。
- 主体轮廓、屋面、悬挑、斜撑、重要洞口/窗框和入口用几何；远处接缝、螺钉和细小窗格可用纹理/法线。不要把重复小窗或螺钉全部拆成动画对象。
- 清理重复面、共面贴片、孤立点及无用内几何；保留动画分解时能看到的板厚、背面、连接处和必要遮挡。法线朝外，硬边/曲面平滑明确，近景倒角有真实尺度。
- 不用全局 doubleSided 掩盖法线错误。封闭不透明外壳默认单面；必要薄片/叶片经检查使用双面。玻璃、灯片、贴花错层，检查近中远距离闪烁。
- 处理负缩放、非均匀缩放、镜像及剪切；有动画后不能随意 Apply Transform 破坏基准。源高模、导出网格和备份可分层，实际低模三角化、UV、法线与切线一致。

## 3. 材质与实际节点

采用 glTF 2.0 metallic-roughness PBR；同一照明下必须能区分玻璃、金属、石材、混凝土等。以下只是首次调材起点，按照片和最终 GLB 校准。

| 材料                     | 制作要求                                              | 起点/限制                                                       |
| ------------------------ | ----------------------------------------------------- | --------------------------------------------------------------- |
| 幕墙玻璃                 | 区分清/镀膜玻璃、框架、胶缝、内部遮挡与板间变化       | 普通玻璃 metallic=0，roughness 约 0.12–0.30；远景可用不透明近似 |
| 裸钢、铝、铜             | 金属颜色、加工方向、倒角与粗糙度有依据                | 连续裸金属通常 metallic=1，roughness 约 0.20–0.45               |
| 漆面/涂层金属            | 按可见涂层的介电特征制作                              | 不因基材为钢就把完整漆面设为 metallic=1                         |
| 石材、混凝土、沥青、橡胶 | 正确尺度的颗粒、板缝、颜色、法线和粗糙度              | metallic=0，roughness 约 0.55–0.95；磨光/潮湿另校准             |
| 金属屋面                 | 立缝、板向、裸面/涂层和轻微板间变化                   | 不能只铺统一银灰色                                              |
| 木材、草地、植被         | 有参考的纹理方向、层次、树冠/叶片形态                 | 避免纯绿大平面和等大球体；叶片检查 MASK                         |
| 窗灯、招牌、轮廓灯       | 独立 Emissive 颜色/遮罩，冷暖、亮暗、暗区和退进有层次 | 不整栋均匀发亮；自发光不等于照亮邻面                            |

必须设置实际连接到 Material Output 的 Principled 节点/可导出纹理。只设置 `material.diffuse_color` 或实体视图颜色不算完成；导出后读取实际 `baseColorFactor`、metallic/roughness、emissive 及纹理绑定。不要依赖节点的本地化显示名，脚本识别节点类型并检查连接。

主体不使用 Unlit 绕过太阳；必要局部 Unlit 独立记录。透明按需要单独分区：叶片/硬遮罩优先 MASK，确需叠层才用 BLEND。没有内部遮挡的全透明空壳通常不能表达可信办公室。Transmission、Volume、IOR 和 GLB 灯光不是当前消费端保证支持的前提；玻璃须提供当前引擎可显示的近似。

程序化节点、复杂涂层或专属渲染器效果先转换/烘焙为可交换材质，不以 Blender 中“看起来对”证明最终文件正确。材质清单记录材料名、使用构件、通道、因子、贴图、UV、尺寸/分辨率、色彩空间及来源。

## 4. UV、纹理与表面变化

| 通道               | 图像/数据语义                             | 必查项                                   |
| ------------------ | ----------------------------------------- | ---------------------------------------- |
| Base Color         | 彩色图按 sRGB；常量因子遵守 glTF 线性语义 | 不烘入固定太阳、整栋投影或照片拍摄光照   |
| Normal             | 线性数据，切线空间，glTF/OpenGL +Y        | DirectX 法线先转换，检查切线、强度、接缝 |
| Roughness/Metallic | 线性数据，G=roughness、B=metallic         | 物理材料分类正确，不当 sRGB 处理         |
| Occlusion          | 线性数据，R 通道                          | 局部结构/缝隙遮蔽，不替代实时太阳阴影    |
| Emissive           | 彩色图按 sRGB，因子按 glTF 语义           | 独立窗灯布局，与白天材质分离             |

- 每个用图像纹理的 primitive 有对应 `TEXCOORD_n`；不能网格没 UV 却引用贴图。主材质通常用 `TEXCOORD_0`。
- 重复幕墙、屋面和铺装用米制平铺，模块尺寸可信。独占 AO/标志/窗灯布局必要时用第二套非重叠 UV，明确 `textureInfo.texCoord`；无独占需求不强制第二套 UV。
- ORM 可合并 R=AO、G=roughness、B=metallic，但分别绑定两个 textureInfo；UV/布局不同不能硬合并。重叠/镜像只在平铺允许的位置使用。
- 图集按 mipmap 与压缩结果留扩边；2K/4K 可从 8–16 像素试验，低档重新检查串色。曲面、斜幕墙和屋面检查拉伸。
- 常用材质 1K/2K，重要近景可 4K；8K 要有镜头与显存测量理由。局部石材/混凝土可从 256–512 texel/米平铺密度试验，不要求整楼独占巨图。
- 表面变化按板材、楼层和功能区固定分布；roughness 板间差可从 0.01–0.04 试验。克制噪声、污渍和磨损，不能把新玻璃楼做成随机脏点。
- 复用纹理、图集和少量材质；不靠成百上千材质实现随机色。远景复查高频细线、法线和压缩闪烁。照片贴图先校正透视及拍摄光照，检查使用许可。

## 5. 光照、昼夜与预览

### 5.1 Blender 展示

建立独立 `PREVIEW_ONLY` 集合，包含相机、太阳/面积主补光、摄影棚地面和可用 HDRI。建议先用中性柔光检查材质，再用明确的日光、日落和夜景检查形体；不能靠彩色强光掩盖灰模或材料错误。

任务书记录渲染器、Blender 版本、灯位置/方向/能量/尺寸、HDRI 来源/旋转、色彩管理（如 AgX）、曝光、阴影、采样和输出画幅。白天、日落、蓝调、夜间保留同构图对照，再补低机位、侧后方及近景。棚内精修画面与目标引擎对照截图分别命名。

### 5.2 交给 Cyber-Sight 的资产

- GLB 排除预览相机、灯、HDRI、摄影棚地面和辅助标尺；有意义的建筑自带场地可以保留，不能误删为摄影棚。
- 保留静态夜景 Emissive 通道。按楼层、房间组和功能区设置灯位、暗区和明暗/色温差，窗灯与玻璃/室内遮挡保持正确前后关系。发光层随所属部件运动。
- `emissiveFactor` 保持标准范围，需要强度用 `KHR_materials_emissive_strength` 并验文件。不能将运行时适配后的超范围因子回写为标准源资产。
- 不内置本地小时、随机闪窗、第二个昼夜计时器或动画驱动窗灯时钟。消费端以唯一 `viewer.clock` 和模型所在地太阳高度控制夜景；模型拼装进度不改变仿真时间。
- 当前白天权重在太阳高度 +2° 及以上为 0，夜间在 -6° 及以下为 1，中间平滑过渡；这些是消费端行为，不要求模型烘入日期或小时。
- 自带基座可用独立夜间表面近似灯位受光，说明其近似性质；不烘进白天颜色。GLB 自发光不会自动产生对地面/邻楼的真实照明，也不自带城市反射。
- 不依赖 Bloom、工作室灯光或 DEV 示例按材质名改色才能正常观看。实际视口配色、节点材质、最终 GLB 与引擎效果分别检查。

## 6. 地理位置、原点、轴向与高程

### 6.1 全楼锚点

水平统一 WGS84 十进制度，经度 `[-180,180]`、纬度 `[-90,90]`，标识 EPSG:4326。已知绝对高度是 WGS84 椭球高（EPSG:4979，米），不是建筑高、离地高或未经转换的海拔/正高。其他 CRS 在制作端转换，记录方法及误差；未知参考系不能只换标签。

唯一 `GEO_ROOT` 放在可核对的地面基准点，通常建筑或场地底部中心。地下结构可低于零，但记录地面基准。根节点固定，禁止在动画中移动/缩放地理锚点。所有版本同原点、同尺度、同真实北向；新资产按 scale=1、heading/pitch/roll=0 校准，不能把正面朝相机当作北向正确。

当前消费端按 Y-up / Z-forward 转换后，最终 glTF 局部 **+X=北、+Y=上、+Z=东**。常规 Blender Z-up 导出为源 +X→glTF +X、源 +Y→glTF -Z、源 +Z→glTF +Y，因此可采用 **Blender +X=北、+Y=西、+Z=上**，或保留工作坐标并通过一次明确根变换等效校准。不得重复旋转；用北向、入口及路网核对最终文件。

### 6.2 模型 metadata 与手工 URL

地理字段只写活动场景唯一 `GEO_ROOT.extras`，不在每件、`asset.extras` 或多处重复写定位。基本字段如下：

| 字段                                        | 要求                                                 |
| ------------------------------------------- | ---------------------------------------------------- |
| `geo_metadata_version`                      | `1`，制作说明版本                                    |
| `longitude_wgs84` / `latitude_wgs84`        | 有来源的有限数值，不用字符串                         |
| `ellipsoid_height_m`                        | 仅已知真实绝对椭球高时提供；未知省略                 |
| `horizontal_crs` / `vertical_reference`     | `EPSG:4326` / `WGS84_ELLIPSOID`                      |
| `coordinate_source` / `coordinate_accuracy` | 可核对来源；`surveyed` / `reference` / `approximate` |
| `height_source`                             | 已知高度的依据；未知为 `terrain_at_load`             |
| `units` / `local_origin`                    | `meters` 和明确锚点描述                              |
| `height_m`                                  | 有依据的建筑尺寸，仅用于说明，不表示定位高度         |

示例仅表示未知椭球高的近似上海中心锚点，不是实测坐标：

```json
{
  "name": "GEO_ROOT",
  "extras": {
    "geo_metadata_version": 1,
    "longitude_wgs84": 121.5011,
    "latitude_wgs84": 31.23356,
    "horizontal_crs": "EPSG:4326",
    "vertical_reference": "WGS84_ELLIPSOID",
    "coordinate_source": "公开资料建筑中心近似；实际交付填写来源",
    "coordinate_accuracy": "approximate",
    "height_source": "terrain_at_load",
    "units": "meters",
    "local_origin": "ground_anchor_at_building_base_center"
  }
}
```

可附同版本 `placement.json`，记录上述字段、URL、手工姿态与尺寸依据。当前手工 URL 加载读取 GLB 明确坐标并让用户选择来源，选择模型坐标且高度缺失时采样当前地形；不会自动请求 `placement.json`，也不自动解释偏移/高度模式等自创字段。未知值不用 NaN、Infinity、空字符串或 null 伪装。

### 6.3 发布目录 v1

[发布协议](publishing-protocol.md)中的 `model.source.json` 经工具生成 `model.json`，其 `placement` 必须有 `height`（椭球高）和姿态/比例。目录使用已发布定位，不再次询问 GLB 坐标；发布字段命名与制作端 metadata 不同，必须逐项核对。

真实高程未知时，不能为了填发布表把 0 说成已知地面。先补可靠定位，或明确创建 `terrain: ellipsoid` 的演示项并在 `notice` 中说明 0 是展示高度、位置为近似。不能声称这样的目录项会自动在真实地形采样。部件的局部坐标始终不使用经纬度。

## 7. 部件划分、枢轴与清单

按真实建筑及表现任务划分逻辑件：基础/基座、核心筒、楼板、柱梁/斜撑、立面分区、裙房/入口、屋面/冠部、重要设备、自带场地/景观。机场按航站楼/指廊/屋盖模块，壳体按板片/结构带，资料不足的内部件标示意；不强迫所有建筑都有相同类别。

```text
GEO_ROOT
  STATIC_SITE
  PART_floor_L03_slab_01
    MESH_floor_L03_slab_01_concrete
  PART_facade_L03_N_01
    MESH_facade_L03_N_01_glass
    MESH_facade_L03_N_01_frame
    MESH_facade_L03_N_01_emissive
PREVIEW_ONLY                      仅源工程预览，不随 GLB 导出
```

- 每个独立运动件有唯一稳定 `part_id`，例如 `floor_L03_slab_01`，以及导出后可核对的节点名。记录类别、楼层、区域、依赖、阶段、顺序和是否参与动画。
- 单一构件中的框架、玻璃、窗灯、贴花和内部遮挡随同一个枢轴运动。可共享 mesh、材质与纹理，但不能把独立运动件合并掉。Collection 只是组织方式，验最终节点树。
- 枢轴在构件中心、安装点或连接点，说明理由；保存原始装配 TRS。默认可动画 PART 直属固定根，网格在其局部坐标中制作；复杂层级写清固定父级并正确转换局部坐标。
- `parts.json` 统一使用 `gltf-local-y-up`；TRS、爆炸偏移和路径都以所列父节点为坐标框架。Blender world location 与父级 local translation 不可混用；Blender 四元数 WXYZ 要转换成 glTF XYZW 并归一化。
- 静态版本可按材质/可见区域合并优化；保留源部件映射。动画质量降级采用组级运动并列 `source_part_ids`，不默默丢件。动态节点不依赖尚未验过的 GPU 实例变换动画。

`parts.json` 最少记录：版本/坐标框架、稳定 ID、node/parent 名、类别/楼层/区域、枢轴定义、装配 TRS、爆炸偏移、起点/途经点、起止时间、顺序和依赖。下面是单个基座件的说明示例，不是已交付模型或 Geo 网络 Schema：

```json
{
  "version": 1,
  "standard_id": "CS-AM-1",
  "coordinate_frame": "gltf-local-y-up",
  "units": "meters",
  "parts": [
    {
      "part_id": "base_01",
      "node_name": "PART_base_01",
      "parent_node_name": "GEO_ROOT",
      "category": "base",
      "level": "L00",
      "zone": "main",
      "animated": true,
      "pivot_note": "基座底部中心；网格相对此枢轴制作",
      "assembled": {
        "translation_m": [0, 0, 0],
        "rotation_xyzw": [0, 0, 0, 1],
        "scale": [1, 1, 1]
      },
      "explode_offset_m": [0, 3, 0],
      "assembly": {
        "phase": "base",
        "order": 1,
        "start_s": 1,
        "end_s": 2.2,
        "spawn_translation_m": [0, 8, -15],
        "waypoints_m": [[0, 5, -5]],
        "depends_on": []
      }
    }
  ]
}
```

## 8. 爆炸分解与从无到有的飞入拼装

### 8.1 共有规则

分解/拼装是确定性节点运动；全楼根锚点不动。先存装配矩阵，再从它生成两种动画，不累计在上一帧的位置上。所有部件同一时间原点，每个进度可直接采样；暂停、倒拖和重播不依赖上一次播放状态。

爆炸按楼层向上拉开、立面沿外法向展开或结构系统分组展开，保持朝向和逻辑关系。间距可从层高 1–3 倍、立面模块尺寸 0.5–2 倍试验，按镜头和建筑调整；不是固定把所有构件移相同米数。爆炸建议 8–12 秒、末态保持至少 2 秒，实际值写任务书。

拼装必须看得出构件逐步飞入并落位。只做整楼缩放、逐层开关可见性或全部同时冲入，均不算满足目标。默认从基础/核心 → 楼层结构 → 立面分区 → 屋面冠部 → 入口/附属物/场地收尾；可按真实结构调整，并记录安装依赖。艺术路径不等于工程施工顺序。

### 8.2 路径与空场

起点在建筑外、靠近工作区，从所属侧或上方进入，必要时加 1–2 个避让点。用实际包围盒检查地面、邻件和已完成结构穿插，避免飞行路径切穿整栋或从地底冒出。无法避免的艺术性穿插明确标注，不冒充物理装配。

空场先采用近距离镜头外待机加极小正比例（如 `1e-4`），在入镜前恢复完整尺寸；不要使用百万米偏移藏构件。零缩放涉及奇异变换，仅在目标引擎检查通过后采用；即使非零比例也检查首帧点状漏件、影子和轮廓。Blender 的隐藏开关动画与材质 alpha 动画不作为核心 glTF 基线。

任务书明确空场是否保留自带基座/景观，默认主体建筑消失，不能一开始仍有完整静态副本叠在同位置。摄影棚地面不属于建筑，正式 GLB 不导出。

### 8.3 时间、缓动和首末状态

默认提案 **30 fps、24 秒、帧 0–720**（720 个帧间隔）。这是排程起点；复杂度、画幅和最终用途决定是否调整，不能归为原会话确认参数。`t=(frame-frame_start)/fps`，glTF 时间单位秒。

| 时间    | 默认内容                 |
| ------- | ------------------------ |
| 0–1 s   | 空场建立                 |
| 1–5 s   | 基础、核心和主要承重结构 |
| 4–13 s  | 楼层/结构错峰搭建        |
| 11–19 s | 幕墙、屋面及冠部         |
| 18–21 s | 入口、附属细节和场地收尾 |
| 21–24 s | 完整成品保持             |

同阶段可重叠，但依赖构件先达到必要安装状态。单件可从 0.5–1.5 秒、相邻启动间隔 0.05–0.20 秒试验；按总时长重新排程，不机械累计。终点减速，旋转克制、走短弧，过冲/弹跳仅按明确风格需求使用。

拼装末帧精确还原装配 TRS，爆炸首帧与静态成品一致；保持段不漂移、不闪回。建议文件一致性容差：平移 ≤1 mm、旋转 ≤0.01°、比例分量误差 ≤`1e-5`；例外量化说明。这些是不同文件姿态对齐要求，不代表建筑测绘精度。

## 9. 动画导出、脚本和文件组织

### 9.1 导出约定

- `<id>.glb` 为无动画完整成品；`<id>-assembly.glb` 只含 `BUILD_ASSEMBLY`；`<id>-explode.glb` 只含 `BUILD_EXPLODE`。不要在一个兼容文件内同时混放互相覆盖的两种 clip。
- 动画文件的非动画节点 TRS 默认完整装配，播放才应用 clip 起点。检查 rest transform 导出选项与最终 JSON，不能只停在 Blender 末帧便假设默认姿态正确。
- 基线采用核心 translation / rotation / scale。约束、路径、驱动、Geometry Nodes/刚体运动先烘焙；会变化的拓扑不能靠 TRS 烘焙解决，须改成固定构件或另行设计。
- 优先把一段全楼表演合并成单 clip，保留每个构件相对于共同 `t=0` 的错峰。不要把每件单独重置起点为零。确需多 clip 的旧工具作为有说明的兼容例外，列全片段和共同时间范围，专门验同步与末帧保持。
- 节点被动画引用时只使用 TRS，不并存 `matrix`。时间非负、严格递增；保留首末帧、启动/到位及保持段。Bezier 缓动采样或正确转换，初次可逐帧采样，简化后再比对。
- 自包含 GLB 2.0 优先，带必要 normals/tangents/UV/材质/纹理/extras。程序化材质先烘焙，导出只选资产层级。不要导出无关预览对象。
- 当前消费基线为 Cesium 1.144.0 / engine 26.2.0；标准 PBR、部分材质扩展、KTX2/BasisU、Meshopt/Draco 的具体结果按实际版本与设备验收。`KHR_materials_emissive_strength` 由消费端适配；Transmission/Volume/IOR/灯光不作为依赖。兼容版本优先基础 PBR、PNG/JPEG。
- 核对 `extensionsUsed/Required`、内嵌图片、textureInfo、材质因子、UV、轴向及节点数。优化后重复检查动画时间、材质和定位。所有 GLB 用 Khronos Validator，无错误，警告逐条处理。

`animation.json` 是制作说明附录，现行 Geo 和发布器不会自动据此控制动画。示例声明一个 24 秒拼装片段；实际完整交付要另列爆炸文件与相应时长：

```json
{
  "version": 1,
  "standard_id": "CS-AM-1",
  "fps": 30,
  "time_origin": "clip_start_seconds",
  "clips": [
    {
      "file": "example-building-assembly.glb",
      "name": "BUILD_ASSEMBLY",
      "frame_start": 0,
      "frame_end": 720,
      "duration_s": 24,
      "hold_start_s": 21,
      "initial_state": "empty_building",
      "final_state": "assembled",
      "default_node_pose": "assembled",
      "loop": false
    }
  ],
  "parts_file": "parts.json",
  "seed": 42
}
```

### 9.2 可编辑源工程与可运行脚本

每个实际建模任务交付 `.blend` 和 `scripts/build_model.py`、`scripts/animate.py`、`scripts/export.py` 或等效可运行入口。README 写明版本、依赖、工作目录、命令、输出路径、fps、时间、种子及导出选项。脚本只操作指定项目资产集合，不清空用户其他场景，不硬编码某台机器路径。

重复执行不叠加对象/材质/关键帧；固定种子和排序，保存装配矩阵与无动画源状态。路径、爆炸间距、阶段和时间参数集中配置，按真实安装 Blender/导出器接口核对，不从不可读的历史答复假装复用脚本。

推荐新项目布局，文件名可按项目约定但须在 README 列清：

可复用环境/空间附件放 `model-assets/`，通用生成/校验工具放 `tools/`。保留完整项目内部相对引用。需交付而被忽略的纹理、参考图、源工程或附件，在 README 明确本地/下载包/公开仓库分别包含什么；不能称 Git 克隆天然获得全部依赖。

## 10. 性能、质量与场景边界

| 类型              | 性能（最佳录屏质量）                    | 平衡                     | 兼容                                 |
| ----------------- | --------------------------------------- | ------------------------ | ------------------------------------ |
| 单栋塔楼/结构建筑 | 约 20–50 万三角面，重点近景可 4K        | 约 8–20 万，通常 1K/2K   | 约 2–8 万，通常 512/1K               |
| 机场/大型建筑群   | 按可见区域分块，整体可从 40–80 万面试验 | 简化设备与远景，保留构型 | 保留主要建筑/屋面/场地，简化次要内容 |

这是制作预算起点，不是硬限制或 FPS 保证。动画可先从约 100–500 个可运动逻辑组试验，复杂建筑附实测例外；不要数万小件同时单独计算。静态和动画分别统计 bytes、三角面、mesh/node、primitive/材质、draw call、纹理占用、动画通道/采样数和峰值运动件数。

测量装配包围盒和动画全程包围范围、首次下载/ready 时间、内存/GPU 占用及录屏设备表现。压缩体积不等于显存；RGBA8 4K 完整 mipmap 约 85 MiB。几何压缩不自动减面/减少批次。不同质量保持锚点、比例、轮廓和分件映射，不能只是改文件名。

建筑自带基座、铺装和必要景观属于主体工程；真实邻楼、街区、道路、地形、城市反射和夜间实际受光属于可独立交付的场景附件。禁止随机城市体块冒充真实周边。相邻地标可复用区域附件，排除重复主体并保存地理参考和署名。

## 11. 发布与当前软件能力

现行 [发布 v1](publishing-protocol.md)只将静态 `<id>.glb` 作为主模型，质量版本列于 `variants`；`resources.kind` 只支持 `3d-tiles | geojson`。不要把动画当质量档或塞入未定义的 `kind`。动画直接文件地址及制作附录列在项目 README，后续目录发现/播放需另做协议及软件工作。

新增/调整正式模型时维护 `model.source.json`，先让目标文件进入 Git 跟踪，再运行 `python tools/catalog/publish.py` 和 `python tools/catalog/publish.py --check`，按[发布指南](vercel-deployment.md)验证发布。本文不会自动增加目录项、重导出旧模型或修改清单 Schema。

当前 Cyber-Sight 的专用拼装面板仅 DEV `/geo.html?assemblyPreview=1`，加载固定 `tmp/building_assembly.glb` 示例，不是通用生产播放器。该示例的灰色修正和柔光对照不属于新资产接口。模型含动画不等于普通 AI 模型卡片已有播放/拖动/选择 clip 功能。

## 12. 交付与验收门槛

每栋建筑交付：填写后的任务书、资料/来源、可编辑源工程、脚本、实际纹理依赖、静态 GLB、适用的两种动画 GLB、定位说明、部件及动画附录、材质清单、资源统计、预览和验证记录。没有实际做的内容标未完成，不用模板勾选冒充结果。

| 阶段                   | 必须核对的证据                                                    |
| ---------------------- | ----------------------------------------------------------------- |
| 资料与建模             | 身份/状态、来源精度、轮廓/比例、北向/入口、拓扑与近景             |
| 材质/照明              | 实际节点、GLB 因子/纹理/UV、日落/夜景、透明遮挡和动画内侧         |
| 定位                   | WGS84 来源、未知高程处理、地面锚点/尺寸/轴向、发布定位一致        |
| 分件与动画             | 部件 ID/依赖、空场、错峰飞入、爆炸层次、首末矩阵一致和完整保持    |
| 文件                   | 静态/动画逐个 Validator、扩展、依赖、bytes/SHA-256、压缩后复验    |
| 脚本                   | 在记录的环境实际运行、输出对应、重复执行可复现、无破坏其他场景    |
| 线上资源（若委托发布） | 部署状态、URL、HTTP、MIME、CORS、完整字节与 SHA-256 匹配          |
| 实际显示/播放          | 目标引擎人工截图、设备/模式/版本、时间和限制；不以 Blender 图替代 |

动画至少检查 0%、25%、50%、75%、100% 及每个阶段边界，保存空场、结构、幕墙、成品和爆炸全貌；测试暂停、随机进度、重播、末帧保持、镜头可见范围与明显穿插。静态成品、拼装末态和爆炸首态同位、同材质；发现未处理差异须记录并修正或明确未通过。

昼夜在同构图比较正午、日落、蓝调和夜间，补入口低机位、侧后方、材料近景及远景环绕。记录绝对时刻/时区、坐标/高程、地形、姿态、质量档、资产版本；3600 倍速检查资产内部没有随机灯光跳变。拼装用局部秒数，不能联动改太阳日期和倍率。

Cyber-Sight 按仓库规则由维护者人工验收前端与浏览器效果，未明确授权不得创建/运行前端自动化或浏览器测试。文档检查、Validator、接口可读、构建成功和真实画面分别代表不同证据；本次规范同步只验证文档及既有发布清单，没有新建筑视觉验收。
